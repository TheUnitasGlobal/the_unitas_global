## 1. 감사가 먼저 뒤집은 두 가지 전제

### 1.1 `/omni-swarm`은 **다크 라우트**다 — quantum-white 토큰이 존재하지 않는다

이 라우트는 `SurfaceScope`를 렌더하지 않는다. 따라서 `html[data-unitas-surface='quantum-white']`가 각인되지 않고, `--qw-ink / --qw-line / --qw-blue / --qw-gold / --qw-glass` 전 계열이 **이 라우트에는 아예 로드되지 않는다**. `OmniSwarmPanel`이 쓰던 `.qw-section-label`조차 무효 클래스였다.

→ 실제로 도달하는 토큰만으로 지어야 한다:
- `--qw-card-*` (THE ONE CARD SKIN, bare `:root`)
- `--u-wl-*` (다크 글래스 계열, `waitlist.css` bare `:root`)
- Tailwind `void(#030305)` · `accent(#d4af37)` · `neon(#00f3ff)`

### 1.2 "글래스모피즘"을 `backdrop-filter`로 지으면 **독트린 위반**이다

두 곳이 스웜을 직접 지목해 금지한다:
- `globals.css` REV-32 문 헤더 — "No filter, no backdrop-filter, no animation loop"
- `quantum-white-rev19.css` §24 — "the swarm field forbids both -- it must stay a still volume, never a blurred one"

**금지 범위는 정확히 `.qw-swarm`(필드)와 `.qw-swarm-portal`(문)이며, 페이지 래퍼·헤더·검색폼·경로·팩트·출처 행은 포함하지 않는다.**

→ 해법은 타협이 아니라 **하우스 기법**이었다. `--u-wl-glass`는 135° 화이트-알파 램프(0.12→0.04)이고 `--u-wl-edge`는 내부 베벨(상단 밝은 인셋 + 하단 어두운 인셋)이다. 둘을 합치면 **blur 없이 유리로 읽힌다** — REV-21 §4.3이 처방한 바로 그 보상이며, 640px blur 레이어가 패럴랙스 프레임마다 재래스터되던 실측이 그 근거다.

## 2. M1 — 시각적 초월

### 2.1 딥 스페이스 (정적)

`[data-omni-swarm-page='page']`에만 적용(허브 탭은 화이트 팝업 안이므로 우주가 새면 안 된다).

- `::before` — 성운: 4겹 `radial-gradient`(시안 #38bdf8 / 바이올렛 #7c3aed / 골드 #d4af37 / 네온 #00f3ff)를 `#030305` 위에. `position: fixed`라 긴 페이지는 우주를 **통과해** 스크롤된다.
- `::after` — 별 알갱이: 1px 도트 격자 2중 스케일(84px / 37px), `mix-blend-mode: screen`, opacity 0.32.

**모든 그라데이션은 한 번만 칠해진다.** 키프레임 0, filter 0, 애니메이션 속성 0 — 깊이는 `transparent` 스톱으로 깃털처럼 흐린 중첩 방사 그라데이션에서 나온다(`​.sp-bg`·`.qw-void-pool`과 같은 어법).

### 2.2 다크 글래스

`--qw-swarm-glass`(135° 램프) + `--qw-swarm-edge`(내부 베벨) + `--qw-swarm-lift`(깊이 그림자)를 한 번 정의하고 검색 콘솔·패널이 소비한다. 필드 프레임(`.qw-swarm-frame`)은 같은 기법의 옅은 버전 — **blur 없이**.

## 3. M2 — 제로-프릭션

### 3.1 세 번 거절한다 (한 번으로는 부족하다)

1. **`touch-action: none`** — 스테이지와 필드 양쪽에. REV-24는 필드에 `pan-y`를 남겨 페이지가 통과 스크롤되게 했는데, 그것이 정확히 멈춰야 할 동작이었다.
2. **비수동 `touchmove` + `preventDefault()`** — React는 터치 핸들러를 passive로 붙이므로 `onTouchMove` prop으로는 아무것도 취소할 수 없다. `{ passive: false }`로 직접 등록해야만 거절이 가능하다.
3. **`gesturestart`/`gesturechange`/`gestureend` 차단** — WebKit 전용 이벤트로, 포인터 모델 **밖에서** 문서 전체 핀치로 발화한다. 이것을 막지 않으면 필드를 핀치하는 동안 iOS Safari가 페이지를 확대한다 — 창립자가 지목한 그 실패다.

범위는 이 박스 한정이다. 스테이지 밖에서 시작한 한 손가락 제스처는 건드리지 않으므로 나머지 페이지 스크롤은 그대로다.

### 3.2 순수 수학 (`lib/swarm/viewportMath.ts`, 26 테스트)

팬은 **스테이지 퍼센트** 단위 — `swarmLayout`이 퍼센트로 말하는 것과 같은 이유(HTML 레이어와 `viewBox="0 0 100 100"` SVG 레이어를 하나의 숫자로 구동).

- `panLimit(z) = (z-1)/2 × 100` — 줌 1에서 0이므로 **딱 맞는 필드는 구조적으로 움직이지 않는다**.
- `zoomTo`는 팬을 **재클램프**한다. 3배에서 합법이던 팬이 1.2배에서는 불법이 되고, 재클램프가 없으면 필드가 중심 밖에 좌초해 리셋 말고는 돌아올 길이 없다.
- `pxToPct`는 줌으로 나눈다 — 안 그러면 손가락 밑에서 필드가 미끄러진다.
- `clampZoom`은 **NaN만** 거절한다(`scale(NaN)`은 요소를 조용히 지운다). 무한대는 오류가 아니라 극단이므로 클램프가 답한다.
- `-0` 정규화 — 산술적으로 0과 같지만 동일하지 않아, 리셋 버튼이 읽는 등가 판정을 동전 던지기로 만든다.

### 3.3 실행 중 발견한 결함 2건 (E2E가 잡았다)

**(a) 리스너를 `dragging` 상태에 묶은 것.** 더 깔끔해 보였고 틀렸다. `setDragging(true)`가 예약한 렌더 **이후에** 이펙트가 붙으므로, 같은 프레임 안에서 down·up이 끝나는 빠른 탭은 **리스너 없이 릴리스**된다. 포인터가 맵에서 제거되지 않아 다음 누름이 두 번째 손가락으로 집계되고, 핀치로 읽혀 `movedRef`가 서고, 그 뒤로는 **어떤 노드도 흡수될 수 없다**. → 무조건 바인딩(맵이 비면 no-op)으로 경합 자체를 제거.

**(b) `setPointerCapture`.** 올바른 도구처럼 읽히고 필드를 조용히 망가뜨린다. 캡처는 해당 포인터의 이후 이벤트를 **캡처 요소로 재타깃**하므로 `pointerup`이 스테이지에 떨어지고, 브라우저는 `click`을 노드가 아니라 **스테이지**에 발화한다. 실측: 평범한 탭이 아무것도 흡수하지 않게 됐다. → 캡처 제거(윈도우 리스너가 이미 박스를 벗어난 포인터를 따라간다).

## 4. M3 — 한계 비용 영구 0원

### 4.1 3계층

| 계층 | 무엇을 답하나 | 수명 |
|---|---|---|
| 모듈 `Map` | 같은 탭에서 같은 주제 — JSON 파싱조차 없이 마이크로초. **흡수 경로의 되돌아가기가 공짜인 이유** | 탭 |
| in-flight `Map` | 두 진입로가 같은 순간 같은 주제를 열 때 해석 1회를 나눠 씀 | 요청 중 |
| **`swarmCache` (localStorage)** | 재방문·새 탭·내일 — **요청 0건** | 7일 |

### 4.2 설계 결정

- **TTL 7일** — `geoCache`엔 TTL이 없다(도시 좌표는 안 변한다). 회사의 자회사와 최고경영자는 변한다. 7일은 REV-25 앵커 브릿지가 해석된 정체성에 쓰던 시계와 같다.
- **빈 결과는 절대 캐시하지 않는다** — "위키데이터에 없음"은 제3자의 한 순간에 대한 진술이지 주제에 대한 진술이 아니다. 일주일 얼리면 일시적 장애가 영구적 빈 필드가 된다.
- **쿼터 초과 시 차가운 절반을 버리고 1회 재시도** — 스웜 행은 ~6KB로 geoCache 행보다 크므로 압력이 실재한다. 실패해도 방문자가 볼 수 있는 오류는 없다.
- 개인정보 페이지 원장(`BROWSER_STORAGE_LEDGER`)에 키를 등록했다 — 이 앱은 쓰는 저장소를 전부 공시한다.
