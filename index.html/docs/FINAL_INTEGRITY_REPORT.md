**워커 없는 대조군과의 격차: +46.3 ms → +11.1 ms.**

> **정정 기록:** 이 문제는 당초 "서비스 워커가 `_next/static`을 **강제 캐싱**한다"고
> 보고되었으나 **사실이 아니었다.** `sw.js`에는 캐시 쓰기가 한 줄도 없고 `activate`는
> Cache Storage를 전부 삭제한다. 실제 기전은 **재발행(re-issue)** 이었다 —
> `respondWith(fetch(req))`가 요청을 워커 컨텍스트에서 새로 띄우는 비용. 캐싱이었다면
> 처방이 퍼지였겠지만 재발행이므로 처방은 **통과(bypass)** 였다. 오진 상태로 고쳤다면
> 틀린 것을 고쳤을 것이다.

**설치 신호는 보존했다.** Chrome 공식 문서상 메뉴 설치 요건에서 fetch 핸들러 요구는
제거됐으나(모바일 108 / 데스크톱 112) **`beforeinstallprompt` 알고리즘은 여전히 존재를
요구**한다. 따라서 핸들러는 남기고 **콘텐츠 해시가 박힌 불변 산출물만** 통과시켰다.

3. 우하단 패널에서 **Run**. 화면이 약 1초 비워지는 것은 **대조군 측정**이며 정상이다.
4. 판정을 읽는다:
   - **`accelerated`** — 이 기기에서 페이지는 기기 바닥 대비 추가 비용이 없다. **조치 불필요.**
   - **`raster-bound`** — 페이지가 실제로 비싸다. **Find bottleneck** 을 눌러 영역별 지분을
     확인한다. 그때 비로소 최적화 대상이 확정된다.
   - **`software`** — 그 브라우저에 GPU 경로가 없다(하네스와 동일 상황).
5. **Copy JSON** 으로 전체 판독(기기 사실 + 케이던스 + 대조군 + 병목 + PWA)을 보존한다.

**판정 설계 원칙:** 절대 예산을 쓰지 않는다. 모든 판정은 ① 구성상 이식 가능(유휴 프레임 0)
이거나 ② **같은 기기·같은 초에 잰 대조군 대비 상대값**이다. 느린 폰은 느린 것이지 고장이
아니기 때문이다.

### 6.2 항목 B — `beforeinstallprompt` 배너 발화

**기술적 한계**

| 사실 | 의미 |
|---|---|
| 헤드리스 브라우저에서 **발화하지 않는다** | Chrome의 실제 프로필 참여 휴리스틱에 걸려 있음 |
| **iOS Safari에는 이 이벤트가 없다** | 어떤 버전에도 없음. 설치는 공유 → 홈 화면에 추가 |
| 워커 fetch 핸들러 유지 근거는 **문서** | Chrome 공식 문서에 근거했을 뿐, 이 하네스로 재현 검증 못 함 |

**이 프로젝트가 소유한 전제는 전부 성립함이 실측되었다**(헤드리스):

```
chromium      waiting · desktop · sw yes · manifest ok · prompt none
mobile-chrome waiting · android · sw yes · manifest ok · prompt none
```

라이브 매니페스트 실측: `name` UNITAS · `icons` 3 · `start_url` `/` · `display` standalone —
판정기가 요구하는 4개 필드 전부 존재. 즉 **`blocked`가 나올 이유가 없다.**

**향후 가이드**

| 플랫폼 | 기대 판정 | 절차 |
|---|---|---|
| **안드로이드 Chrome** | `ready` 또는 `waiting` | `ready`면 **Install** 버튼이 네이티브 다이얼로그를 띄운다. `waiting`이면 페이지와 상호작용 후 재시도 — 이는 Chrome 휴리스틱이지 결함이 아니다 |
| **iOS Safari** | **`ios-manual`** | 공유 → 홈 화면에 추가 → **홈 화면에서 다시 열어** 프로브 재실행. `installed`가 나오면 설치 확인 완료 |

**판정기가 절대 하지 않는 것:** iOS를 `blocked`로 부르지 않는다. 그렇게 보고하면 창립자가
**존재하지 않는 버그를 쫓게 된다.** 마찬가지로 "아직 아님(`waiting`)"과 "불가(`blocked`)"를
분리한다.

### 6.3 항목 C — `backdrop-filter` 3겹

병목 어댑터가 남긴 **유일한 실제 최적화 후보**다. GPU 없는 환경에서 가장 비싼 속성이지만,
실기기 사파리에서는 GPU가 처리한다. **항목 A의 판정 없이 손대면 근거 없는 최적화**가 되므로
A에 묶여 있다.

### 6.4 항목 D — `sovereign:key` 실행

자동 승인 분류기가 **자격증명 실체화를 차단**한다(올바른 동작). 암호 경로는 유닛 20건 +
E2E 30건으로 증명되어 있으며, 프로덕션 키 발행은 창립자가 직접 수행해야 한다.

> **보안 기록:** 저장소에 적힌 **개발 기본 토큰은 프로덕션을 열지 못한다**(라이브 실측
> 307 seal). 프로덕션은 자체 `SOVEREIGN_AUTH_TOKEN`을 사용하며, 이 세션은 그 값을 읽거나
> 출력한 적이 없다.
