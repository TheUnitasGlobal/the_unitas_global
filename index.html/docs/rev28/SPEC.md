## §1. MISSION 1 — 진입 링크

### 1.1 링크 하나로는 해결되지 않는다 (실측)

지령은 창립자가 iOS Safari 실기기에서 진단에 즉시 진입할 수 있는 바로가기를 요구한다.
지령이 적어 준 주소를 실제로 두드려 봤다:

```
https://theunitas.global/?diag=1      -> 308  https://www.theunitas.global/?diag=1
https://www.theunitas.global/?diag=1  -> 307  /en/gateway?diag=1
```

에이펙스는 **쿼리를 보존한 채** www로 넘긴다(정상). 그러나 **세션이 없는 폰에서는
게이트웨이로 봉인된다.** 프로브의 무장 펜스는 `?diag=1`만 보지만, 그 앞에 퍼널이 있고
퍼널 뒤에 서버 창립자 확인이 또 있다. 즉 **링크는 세션을 만들어 주지 못한다.**

조용히 게이트웨이로 떨어지는 바로가기는 바로가기가 없는 것보다 나쁘므로, 두 가지를
같이 넣었다.

| | 구현 | 비고 |
|---|---|---|
| **이 기기** | 소버린 콘솔의 `RENDER PROBE` 액션 — 현재 문서를 `?diag=1`로 재진입 | 이미 인증된 브라우저이므로 한 번 누르면 끝 |
| **다른 기기** | 같은 자리에 명시: *"On another device, pass the founder door there first, then add `?diag=1`"* | 토큰은 창립자만 안다. 이 세션은 생성하지도 저장하지도 않는다 |

콘솔은 이미 서버 검증으로 게이트되어 있으므로 새 보안 표면이 생기지 않는다.

### 1.2 병목 수집 어댑터

`raster-bound`는 "페이지가 비싸다"까지만 말한다. 창립자의 아이폰이 그 판정을 들고 오면
다음 질문은 즉시 **"어디가?"** 다. REV-26은 그 질문에 손으로 답했다 — 링 숨기고 재측정,
nav 숨기고 재측정, 히어로, 검색바... 그 절차를 계측기로 만든 것이
`lib/diagnostics/paintBisect.ts`다.

읽는 법: 각 영역을 숨겨 **회수되는 프레임 시간**을 재고, 그것을 **기기 바닥 대비 페이지
총비용의 지분(%)** 으로 환산한다. "허브가 이 페이지 그리기 비용의 46%"가
"허브 180ms"보다 행동 가능한 정보다.

**이것은 프로파일러가 아니다.** 영역은 겹치고 합성은 가산적이지 않으며 지분은 100%가
되지 않는다. 그래서 `rankRecovery`는 **지분을 정규화하지 않고**, 그 사실을 화면에 띄운다 —
방법이 갖지 못한 정밀도를 발명하지 않기 위해서다.

### 1.3 테스트가 내 임계값을 교정했다

REV-26이 **손으로 "diffuse"라고 결론 낸** 데이터를 그대로 어댑터에 먹였다.
첫 구현은 "최대 기여자" 라인을 20%에 두었고, 그래서 hero(**24.23%**)를 **범인으로 승격**
시켰다 — 앞선 측정이 이미 무죄로 판정한 대상을. 4분의 1은 병목이 아니라 여럿 중 하나다.

밴드를 교정했다: **< 30% = diffuse**, 30–50% = "최대 기여자지만 전부는 아님",
**≥ 50% = 지배적**. 교정 후 어댑터는 REV-26이 손으로 낸 결론과 같은 답을 낸다.

## §2. MISSION 2 — PWA 설치 판정

### 2.1 헤드리스로 증명할 수 없는 것을 증명한 척하지 않는다

REV-26은 워커의 fetch 핸들러를 남긴 근거를 **Chrome 문서**에 두었고,
"`beforeinstallprompt`가 실제로 발화하는지는 이 하네스로 재현 검증하지 못했다"를
미해결로 기록했다. 그것은 지금도 사실이다 — 그 이벤트는 실제 프로필의 참여 휴리스틱을 탄다.

그래서 이벤트를 억지로 띄우려 하는 대신, **실기기가 답할 수 있는 판독기**를 만들었다.

### 2.2 다섯 상태 — 특히 iOS를 고장으로 부르지 않는 것

`lib/diagnostics/pwaReadiness.ts`:

| 상태 | 뜻 |
|---|---|
| `installed` | 이미 standalone으로 실행 중 |
| `ready` | 전제 충족 + `beforeinstallprompt` 포착 → Install 버튼이 네이티브 다이얼로그를 띄운다 |
| `ios-manual` | **iOS에는 어떤 버전에도 설치 프롬프트가 없다.** 공유 → 홈 화면에 추가, 사람이 한다 |
| `waiting` | 전제는 전부 충족인데 이벤트가 아직 안 왔다 (Chrome 휴리스틱) |
| `blocked` | 실제로 막혔다 — 비보안 오리진 / 매니페스트 / 워커 |

**`ios-manual`과 `waiting`을 `blocked`와 분리한 것이 이 모듈의 핵심이다.**
iOS를 실패로 보고하면 창립자가 존재하지 않는 버그를 쫓게 되고, "아직 아님"을 "불가"로
보고하면 멀쩡한 전제를 뜯어고치게 된다. 그리고 `ios-manual`은 **설치 후 확인 방법까지**
말한다 — 홈 화면에서 다시 열어 프로브를 돌리면 `installed`가 나와야 한다.

iPadOS 13+는 데스크톱 Mac UA를 보내므로 `detectPlatform`은 `maxTouchPoints`로 가른다.

### 2.3 E2E가 전제 붕괴를 잡는다

헤드리스에서 상태는 `waiting`이어야 한다 — 이벤트는 안 오지만 **이 프로젝트가 소유한
전제(매니페스트·워커)는 전부 성립**하기 때문이다. 그래서 E2E는 상태가 `blocked`로
나오면 **블로커 목록을 담아 실패**시킨다. REV-26이 워커를 바꿨으니, 그 변경이 설치
전제를 깨뜨렸다면 여기서 즉시 드러난다.

실측(chromium 헤드리스): `waiting · desktop · sw yes · manifest ok · prompt none`.
**워커는 제어 중이고 매니페스트는 정상이다** — REV-26의 변경은 설치 전제를 깨지 않았다.

## §3. 비용 — 계측기는 자기 규율을 지킨다

REV-26이 세운 3중 펜스가 그대로 유지된다: `?diag=1` 없으면 **동적 import 자체가 없고**,
플래그가 있어도 서버 창립자 확인 전엔 `null`, 확인돼도 **Run 전엔 측정 0**.
REV-28이 더한 것 중 측정을 수반하는 것은 **별도 버튼(Find bottleneck)** 뒤에 있고,
PWA 판독은 프레임을 전혀 쓰지 않으므로(사실 수집뿐) 창립자 확인 직후 한 번만 읽는다.

신규 i18n 키 **0개** — 판독기의 라벨은 산문이 아니라 계측 라벨이며, 소버린 콘솔이 이미
택한 방식과 같다.

## §4. 남은 것

- **실기기 실행은 여전히 창립자의 손이 필요하다.** 계측기는 더 날카로워졌지만
  (이제 "어디가 비싼가"까지 답한다), 실제 아이폰 수치는 창립자가 그 기기에서 창립자 문을
  통과한 뒤 `RENDER PROBE`를 눌러야 나온다.
- **`beforeinstallprompt`의 실제 발화는 여전히 헤드리스에서 재현 불가**다. 판독기가
  실기기에서 `ready`를 보고하고 Install이 네이티브 다이얼로그를 띄우는 것을 확인하면
  그때 REV-26의 미해결이 닫힌다.
- `sovereign:key` 실행은 자동 승인 분류기가 계속 차단(올바른 동작).
