## 4. 완주에 필요한 시간 — 산술

### 샤드 1개
```
600s  무장(모든 신호 ≥ idle-min 10분)
+ 60s  틱 지연 (--interval-sec 기본값)
+120s  webServer 부팅 (tests/web-cinema.config.js: timeout 120_000)
+900~1800s  샤드 실행 (실측 chromium 1672s / 설계 추정 15~25분)
= 1500~2580초 = 25~43분의 무중단 부재
```

### 6샤드 전체
`SWEEP_PROJECTS` = chromium · webkit · mobile-chrome · tablet · inapp-kakao · inapp-instagram

```
연속 1회 창:  600 + 60 + 6 × (60 + 120 + 900~1800) = 7140~12540초 = 2.0~3.5시간
분할 6회 창:  6 × (25~43분) = 150~258분 (그 사이 커밋·리빌드 0건 조건)
```

**관측된 최장 무접촉 6.8분 대비 — 샤드 1개에 3.7~6.3배, 무장선에조차 1.47배 못 미친다.**

## 5. 완주를 막는 4중 장치 (전부 의도된 설계다)

1. **무장 조건 (`computeIdle`, `idle-sensor-core.mjs:157-176`)**
   네 신호 **전부** ≥ 10분 + 바쁜 프로세스 0. 읽을 수 없는 신호는 "지금 활동 중"으로 센다(fail-closed).

2. **취소 조건 (`cancelReasons`, `:188-203`) — 무장 조건보다 훨씬 엄격하다**
   임계가 아니라 **스윕 시작 시각** 기준이다. 어떤 신호든 `ts > sweepStartedAt`이면 즉시 취소. 60초마다 재평가되므로 **창립자 메시지 1건이 ≤60초 안에 구동 중인 샤드를 죽인다.**

3. **취소된 샤드는 체크포인트되지 않는다 (`idle-sensor-daemon.mjs:670`)**
   ```js
   if (summary.status === 'cancelled') return;   // ← recordShard / writeProgress 앞에 있다
   ```
   키 입력 1회가 최대 30분의 실행을 버린다.

4. **스윕 키 이탈 (`shardState`, `idle-sensor-core.mjs:626`)**
   키는 `BUILD_ID@HEAD`. 키가 바뀌면 적립분을 **전량 폐기**한다.
   실측: 230분간 키 7종, **평균 수명 32.8분** — 단일 샤드 요구(25~43분) 구간 안이다.
   **완벽한 야간 부재조차 커밋 1회 또는 리빌드 1회에 무효화된다.**

## 6. `transcript` 신호가 왜 세션 중 절대 조용해지지 않는가

`transcript` = `~/.claude/projects/**/*.jsonl`(깊이 4) **전 프로젝트 전 파일의 최대 mtime**.

- 실측 2,454개 파일. **서브에이전트·워크플로 트랜스크립트가 전부 포함된다.**
- 검증 워크플로를 **한 번** 돌린 것만으로 10분 내 11개 파일이 갱신되었다(최신 0.2분).
- claude-mem 옵저버는 세션 활동 40~60초 **뒤에** 쓴다 — 대화를 멈춰도 꼬리가 남는다.
- **다른 프로젝트의 Claude 세션도 활동으로 잡힌다**(의도된 설계).

같은 231분 관측 창에서 **데몬 자체가 107.8분(47%) 죽어 있었다.**
틱 67(04:54:50Z) → 틱 1(06:42:39Z) 카운터 리셋 = 프로세스 사망 + 예약 작업 재기동.

## 8. 에이전트 행동 규범 (이 문서의 실행부)

### 하지 말 것

- ❌ **전경에서 3엔진 전수를 돌리지 마라.** `READER.md:26` 정본: *"전경에서 3엔진 전수를 다시 돌리지 않는다."*
- ❌ **`--idle-min 0`으로 데몬을 강제 기동하지 마라.** 무장 즉시 취소 → 재무장 → 재취소의 무한 처닝만 만든다(취소는 체크포인트되지 않으므로 순손실).
- ❌ **"10분만 기다렸다가 말 걸기" 패턴을 쓰지 마라.** 무장에는 닿아도 완주에는 절대 닿지 않는다. 오히려 샤드 1개를 죽인다.
- ❌ **수동 Playwright 재실행 시 `--output=test-results/stage3-artifacts`를 빼지 마라.** Playwright는 시작 시 `outputDir`을 비우고, 기본값 `test-results/` 아래에 `test-results/stage3/`가 산다. 2026-09-18 이 실수로 **4샤드(chromium 228 · webkit 211 · mobile-chrome 238 · tablet)를 실제로 잃었다.**
- ❌ **스윕 대기 중에 커밋하거나 리빌드하지 마라.** 키가 바뀌어 적립분이 증발한다.
- ❌ **제5장 위반 금지:** 무인 시간대에 LLM을 기동해 이 조건을 "자동으로" 만족시키려 들지 마라. 데몬은 모델 무관·토큰 0이어야 한다.

### 할 것

- ✅ 게이트 5(스윕 완주)가 미충족이면 **`done`으로 승격하지 말고 그대로 보고하라**(제14장 미측정 완료 보고 금지).
- ✅ 나머지 게이트(typecheck · vitest · build · trust:verify)는 전경에서 즉시 실측하고 숫자로 보고하라.
- ✅ 판정은 `latest.md` → `latest.json` 순으로 읽되, **누적 실적은 반드시 `progress.json`에서 읽어라.** 취소된 샤드의 `latest.md`는 `0/0/0`으로 보이는데 그건 그 샤드의 기록이지 스윕 전체가 아니다.
- ✅ 실행 창을 만드는 유일한 방법을 그대로 안내하라: **머신을 깨운 채, 사람이 자리를 비우고, 그 사이 커밋·리빌드 없이, 데몬 생존.** 실무적으로는 취침 시간이다.
