## 1. 현황 실측 — 무엇이 끊겼는가

REV-31이 "더 깊이 탐색"을 소거하면서 스웜의 **유일한** 진입로가 함께 사라졌다. 감사 실측:

- 스웜 도달 경로는 단 하나 — 엔티티 앵커 → `bigTechPulse` 렌즈 타일 클릭 → `DeeperThemePage` → `swarmDimensions.length > 0` 게이트.
- 라우트·API 핸들러·동적 import·`React.lazy` 어디에도 대체 경로 없음(전수 스윕 0건).
- 즉 모듈은 **깨지지 않고 도달 불가**가 됐다 — 아무것도 실패하지 않으므로 더 나쁜 상태다.

### 1.1 복원 대상의 의존성 실측

| 모듈 | import | 판정 |
|---|---|---|
| `swarmLayout.ts` (168줄) | **없음**(순수) | 그대로 복원 |
| `OmniTechSwarm.tsx` (209줄) | React · `useSpatialAudio`(보존됨) · `swarmLayout` | 그대로 복원, import 1줄만 재지정 |
| `omniTech.ts` (207줄) | `deeperFetch`(보존됨) · `deeperThemes` 타입 6종(삭제됨) | 로직 보존, 타입만 재정의 |

→ 렌더링·기하·해체 로직은 **한 줄도 다시 쓰지 않는다**. 바꾸는 것은 그 위의 천장뿐이다.

### 1.2 게이트 함정 실측 (감사가 잡아낸 빌드 블로커)

- **`scripts/validate-module-registry.mjs`가 prebuild에서 `process.exit(1)`** — `app/[locale]/` 아래 미등록 최상위 폴더를 거부한다. `omni-swarm`을 `INFRA_ROUTES`에 등록하지 않으면 Next가 컴파일을 시작하기도 전에 빌드가 닫힌다.
- **`lib/seo/routes.ts`의 `PUBLIC_ROUTES`** + `__tests__/seo/routes.test.ts`의 고정 카운트 2개(17→18, 340→360).
- **`__tests__/uai/streamKindParity.test.ts`의 `FOUNDER_ELEVEN`** — 스트림 kind를 11개로 못 박은 계약. 새 kind는 이 계약을 명시적으로 갱신해야 한다(삭제된 16종 부활 방지 목록 `DELETED_KINDS`는 그대로 유지).
- **`WIKIMEDIA_PAGE_BUDGET = 2`** — 페이지당 위키미디어 호출 상한. 스웜은 자신을 그리는 데 4호출을 쓰므로, 페이지 1에 인라인으로 넣으면 예산이 두 배가 된다.
- 미들웨어 퍼널 게이트는 새 라우트를 **자동으로** 봉인한다(비소버린·비인덱서 307 → `/gateway`). 면제 목록에 넣지 말 것 — 콘텐츠 페이지를 면제하면 사전 출시 퍼널에 구멍이 뚫린다.

## 2. 구현 설계

### 2.1 M1 — 독립 모듈 `lib/swarm/` + `components/swarm/`

| 파일 | 성격 |
|---|---|
| `lib/swarm/swarmLayout.ts` | REV-24 원본 **그대로**(순수 기하, import 0) |
| `lib/swarm/swarmTypes.ts` | **신규** — 스웜이 소유하는 4개 형상(`SwarmCard`/`Item`/`Page`/`Context`). 렌즈 프레임워크의 `DeeperPage` 계열을 대체 |
| `lib/swarm/omniTechSource.ts` | REV-23 해체 로직 **그대로** — 동일한 `wbgetentities` 2회, 동일한 6개 프로퍼티(P452·P749·P355·P1056·P112·P169), 동일한 상한·랭킹·첫 페이지 스케일 팩트. 바뀐 것은 import와 형상 이름뿐 |
| `lib/swarm/useOmniSwarm.ts` | **신규** — `useDeeperPage`(218줄 범용 렌즈 페이저) 대체. 커서를 끝까지 걸어 **한 번에** 공개한다. 반쯤 그려진 필드는 짧은 필드가 아니라 **틀린 그래프**이기 때문(섹터가 차원 수에서 나온다). 모듈 레벨 캐시 + in-flight 맵으로 두 진입로가 한 번의 해석을 나눠 쓴다 |
| `components/swarm/OmniTechSwarm.tsx` | REV-24 원본 **그대로**(WebGL 0 · 렌더루프 0 · 실버튼) |
| `components/swarm/OmniSwarmPanel.tsx` | **신규** — `DeeperThemePage`(361줄) 대체. 필드가 곧 페이지다 |
| `components/swarm/OmniSwarmWorkspace.tsx` | **신규** — 주제 선택(검색/딥링크). `variant`로 라우트와 허브 탭이 **같은 구현**을 공유 |
| `app/[locale]/omni-swarm/page.tsx` | **신규 독립 라우트** — `?qid=Q…`(정규식 검증) / `?q=<이름>`(자체 해석), 자체 canonical + 20 로케일 hreflang |

**격상의 실체**: 라우트는 주소를 갖는다는 뜻이다 — 북마크 가능, 공유 가능, 딥링크 가능, 그리고 무엇에도 의존하지 않는다.

**새로 더한 단 하나**: 흡수 경로(breadcrumb). 노드를 활성화하면 앵커가 조용히 바뀌던 과거에는 Microsoft → OpenAI → Sam Altman으로 걸어가도 돌아올 길도, 걸어왔다는 감각도 없었다. 경로가 기록되면서 "모듈식 흡수" 루프가 **가역적이고 가시적**이 된다.

### 2.2 M2 — 세 개의 진입로

| 진입로 | 위치 | 성격 |
|---|---|---|
| **독립 라우트** | `/<locale>/omni-swarm` | 주소 그 자체 |
| **UNITAS 마스터 허브** | 6번째 탭 (`data-hub-tab-btn="swarm"`) | 허브는 모든 페이지에서 닿는 유일한 표면 |
| **U-AI 결과 메인 팝업** | 페이지 1의 `data-stream-card="swarm"` | 포털 카드 = **문**이지 창이 아니다 |

**왜 포털이고 인라인 필드가 아닌가.** U-AI 결과 페이지에는 `WIKIMEDIA_PAGE_BUDGET = 2`라는 하드 예산이 있고, 이는 스트림 캡까지 전 페이지에 대해 단위 테스트가 단언한다. 스웜은 자신을 그리는 데 위키데이터 4호출을 쓴다. 페이지 1에 인라인으로 렌더하면 **한 번도 보지 않을 방문자까지 포함해** 모든 방문자의 네트워크 비용이 두 배가 된다. 그래서 페이지 위의 카드는 **비용 0**이고, 4호출은 누군가 문을 통과할 때만 쓰인다. 한계비용 0원(Codex §2 #160·#309·#409).

**문은 둘, 부재는 없다.** 첫 구현은 QID 없는 앵커에서 포털을 지웠다. 그리고 chromium E2E가 즉시 증명했다 — 라이브 웹 합성은 최선노력 키리스 패스라서 "Microsoft" 검색에서도 텍스트 앵커로 떨어졌고, 창립자가 요구한 "가장 눈에 띄는 독립된 구역"이 **결과에서 통째로 사라졌다**. REV-32가 고치려던 바로 그 병이다.

그래서 식별자는 **문의 유무가 아니라 문의 방식**을 정한다:

| 앵커 | 문 | 동작 |
|---|---|---|
| QID 있음 | `<button>` | 중첩 모달로 **그 자리에서** 필드를 연다(스크롤 위치 보존, 히스토리 1층) |
| QID 없음 | `<Link>` | 질의를 실어 독립 라우트로 보낸다 — 거기엔 스트림 합성이 건너뛰는 **위키데이터 폴백까지 갖춘 완전 해석기**가 있다 |

둘 중 하나는 **항상** 있고, 어느 쪽도 막다른 길이 아니다.

**충돌 회피**: 포털은 스트림 카드 계열에 속한다 — 동일 radius, 동일 테두리 두께, 동일 바탕. 구분되는 것은 액센트와 정적 radial bloom 하나뿐이다. E2E가 "다른플랫폼에서열기" 행과의 **기하학적 겹침 0**을 실측한다.

### 2.3 i18n

- **차원 라벨·스케일 팩트·브랜드 타이틀·재앵커 문구는 REV-23 원본을 pre-REV-31 트리에서 회수**해 각 로케일이 이미 갖고 있던 표현을 그대로 유지했다(재번역 아님).

- `Rev29.hub.tabs.swarm`은 REV-32 적용기가 쓴다.

### 2.4 CSS

REV-24 스웜 블록(globals 211줄 + 화이트 표면 37줄)을 **원본 그대로** 복원하고 두 개의 죽은 참조만 재지정했다: 컴포넌트 경로, 그리고 렌즈 카드가 제공하던 클리핑 계약 → 스웜 자신의 `.qw-swarm-frame`(`contain: layout paint`, 레이아웃 모듈의 `EDGE_MARGIN` 추론이 의존하는 바로 그 봉쇄).

허브 토글의 아이콘 롤은 5종 → 6종으로 확장했다. **스텝 2.4초는 상수이고 루프 길이가 변수다**(12s → 14.4s) — 케이던스가 계약이지 루프가 계약이 아니기 때문.

## 3. 검증 계약

| 계약 | 위치 |
|---|---|
| 기하 순수성 | `web/__tests__/uai/swarmLayout.test.ts` (복원) |
| 해체 로직 | `web/__tests__/uai/omniTechSwarm.test.ts` (복원, 목 위키데이터) |

E2E는 **결정론적인 것과 제3자 의존인 것을 분리**한다. 라우트 존재·허브 6번째 탭·패널 자가상태·포털 계약·겹침 0은 무조건 단언한다. 실제로 그려진 필드만 라이브 위키데이터에 의존하며, 그 경우 조용히 실패하는 대신 **이유를 밝히고 skip**한다(해체 자체는 목 위키데이터로 단위 테스트가 증명한다).

## 4. 알려진 한계

- 스웜은 **조직**을 해체한다. 사람·장소·개념 앵커는 위키데이터에 해당 프로퍼티가 없어 빈 필드가 된다 — 패널이 그 사실을 문장으로 말한다(추측하지 않는다).
- 라이브 위키데이터가 응답하지 않는 런에서는 필드가 비어 있고, E2E는 그 사실을 **이유와 함께 skip**한다. 해체 로직 자체는 목 위키데이터로 단위 테스트가 결정론적으로 증명한다.
